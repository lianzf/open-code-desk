# 故障排查指南

先记录应用版本、操作系统、问题发生时间、工作区类型、实际错误文字和稳定复现步骤。不要在截图、终端输出或问题报告中附带 API Key、Token、`.env` 内容、数据库或私有源码。

## 应用无法安装或启动

1. 从同一发布页重新下载安装包和 `SHA256SUMS.txt`，核对哈希；正式 Windows/macOS 构建还必须验证平台签名。
2. 不要通过关闭 SmartScreen、Gatekeeper、杀毒软件或系统凭据服务来“解决”问题。未签名测试包只能在受控开发环境使用。
3. 完全退出已有 OpenCode Desk 进程后重试；若安装器报告文件占用，先确认没有仍在运行的终端、运行任务或调试进程。
4. 首屏白屏或立即退出时，记录退出时间并查看设置中的本地崩溃报告。原始用户数据不要直接发给维护者。

需要重置状态时，先退出应用并整体备份 Electron `userData` 目录。不要在应用运行时单独删除 `open-code-desk.sqlite`、`-wal` 或 `-shm` 文件。完整重置会永久删除本地会话、配置、历史和加密 Secret，详见[隐私与本地数据说明](privacy.md)。

## Provider 或模型连接失败

- Base URL 必须是完整 URL，不能包含用户名、密码、查询参数或片段。
- 远程服务必须使用公网 HTTPS；HTTP 只允许本机回环服务，HTTPS 也不能解析到本机、私网或保留地址。
- 检查 API Key 权限、Model ID、服务区域、账户额度和系统时间。401/403、404、429、超时和上下文过长应按界面分类处理。
- 应用拒绝跨源重定向携带凭据，也不会自动放宽自定义 Header 或网络策略。
- Linux 保存密钥失败时，先解锁 Secret Service/KWallet。若系统只能提供 `basic_text`，应用会安全失败，不能改为明文保存。

可以先使用“测试连接”和“刷新模型列表”缩小范围。公开问题报告只应包含脱敏后的状态码、错误类别和服务域名。

## 项目、文件或 Diff 失败

- 确认当前显式打开的是目标工作区；历史工作区 ID 不再授予磁盘访问。
- 检查文件是否在工作区边界内、是否经过符号链接/junction 逃逸、是否命中敏感路径或用户阻止规则。
- “文件已在外部修改”表示基线哈希失效。刷新文件并重新生成提案，不要覆盖磁盘上的新内容。
- AI 修改只有进入 Diff、由用户批准并再次校验基线后才会落盘；失败事务应保留可恢复 Artifact，不要手工删除 `change-artifacts`。
- 大文件、二进制文件和超出资源上限的搜索会被拒绝或截断，这是安全边界而非编辑器损坏。

## 命令、终端、任务或运行失败

- 查看界面显示的 executable、参数数组、工作目录、风险级别、stdout/stderr、退出码和超时原因。
- 批准绑定到完整命令快照；修改参数、目录、环境文件或脚本内容后旧批准失效，需要重新审核。
- 端口冲突时核对 PID 和进程名。终止外部进程必须显式确认，不要凭端口号盲目结束系统服务。
- 停止后若仍有进程，先在应用中执行“全部停止”并正常退出，再使用系统任务管理器确认父子进程；记录 PID 和命令，不要直接批量结束无关 Node/Python 进程。
- Linux/macOS 打包应用若终端无法启动，应核对发布 SBOM 与运行时校验结果；缺少目标平台 `node-pty` 原生模块的交叉产物不是有效安装包。

## Node.js、Python、浏览器、Electron、Java、C/C++、Rust、Go 或 .NET 调试失败

- Node.js/TypeScript、Python、浏览器、Electron 和 Java Adapter 随应用分发。Electron 项目仍需在工作区安装自身声明的 Electron 运行时；Java 仍要求本机提供 JDK 21+ 作为 JDT LS 运行时；C/C++/Rust、Go 和 .NET 分别使用系统安装的外部 `lldb-dap`、`dlv` 和 `netcoredbg`。
- 检查入口文件、解释器/Node 路径、工作目录、参数、环境引用和启动审批。
- React、Vue 或 Next.js 浏览器调试要求运行配置包含端口。常见开发脚本会自动建议端口；手动配置时请确保该端口未被占用，并让开发服务器监听本机回环地址。应用会先启动经审批的开发服务器，再启动已安装的 Chrome 或 Edge。
- 浏览器调试若提示端口已占用，请停止旧服务或修改配置端口；不要绕过 PID 复核批量终止进程。若提示找不到浏览器，请安装 Chrome/Edge 或确认其标准安装路径/PATH 可解析。
- Electron 调试要求配置指向真实 `electron` 可执行文件，并保留一个未占用的渲染进程调试端口。端口已被占用时会在启动 Electron 前失败，避免附加到其他本机进程；不要把该端口绑定到 `0.0.0.0` 或暴露到局域网。主进程断点命中但渲染断点未验证时，确认窗口已创建、页面 URL 属于当前应用，并在渲染目标加载后重试或刷新页面。
- Python 优先使用工作区 `.venv`/`venv`/`env`；无法自动发现时可手动选择解释器。当前不支持 `-c`、attach 和远程调试。
- Node.js 远程/容器附加要求目标已开启 Inspector，且配置端口从本机可达。远程场景优先使用 SSH 本机端口转发；容器端口只映射到 `127.0.0.1`。`remoteRoot` 必须是目标上的绝对源码根目录并与本地工作区内容对应。应用不会创建隧道、运行 Docker 命令或终止目标进程。
- Java 若提示缺少运行时，请把 `JDTLS_JAVA_HOME` 或 `JAVA_HOME` 指向 JDK 21+，然后重启应用；无需修改系统 PATH，也不要把 JRE 17 当作 JDT LS 运行时。Maven/Gradle 项目首次调试会先导入、增量编译并解析主类；存在多个 `main` 类时，请创建直接 Java 配置并把完全限定类名放在程序参数第一项。
- C/C++/Rust 先安装包含 `lldb-dap` 的 LLVM 工具链，并确认终端执行 `lldb-dap --help` 可成功（LLVM 22.1.8 的 `lldb-dap` 不提供 `--version`）。部分 Windows LLVM 包还要求 `python311.dll` 可被加载；若启动即退出并提示缺少该 DLL，请安装匹配架构的 Python 3.11 并把其根目录加入调试环境 PATH。当前应用不会自动下载或静默安装调试器。
- C/C++/Rust 的运行配置必须指向已编译的可执行文件，不能直接把 `cargo`、`cmake`、`make`、`ninja` 或 `msbuild` 当作调试目标；需要构建时，请把构建命令配置为 pre-debug ProjectTask。
- Go 先安装 Delve 并确认 `dlv version` 可成功。默认 `go run <package>` 建议会映射为 Delve `debug` 模式；复杂构建参数请改用 pre-debug ProjectTask，或先生成二进制后使用 `exec` 模式。
- .NET 先安装 NetCoreDbg 并确认 `netcoredbg --version` 可成功。调试配置必须指向已构建的 `.dll` 或 `.exe`，不能直接使用 `dotnet run/build`；构建步骤应放入 pre-debug ProjectTask。
- 查看断点状态：pending、unverified 或 Adapter 明确不支持时不能视为命中成功。函数/数据断点取决于 Adapter capability。
- 调试控制台中的 DAP 请求、开发服务器输出、超时、异常和进程退出信息比编辑器图标更权威。停止或重启后确认旧 Adapter/debuggee、浏览器及开发服务器已退出。
- AI 修复只生成待审核 Diff；批准后仍需用户显式重新调试，应用不会自动修改变量或跳过代码。

## 更新失败

更新仅在已安装版本中可用，默认不自动下载或退出时安装。检查 GitHub Release 可访问性、代理/防火墙、当前版本和目标版本；不要从非官方地址手工替换 ASAR 或调试适配器。正式产物必须通过哈希、签名和 notarization 校验。

## 可安全提供的诊断材料

- 版本、平台、时间、复现步骤和脱敏错误文字。
- 设置页中的本地崩溃报告摘要。
- 工作台审计面板中的相关事件和退出码。
- 不含源码/Secret 的最小复现项目。
- `SHA256SUMS.txt`、SBOM 和依赖/许可证/Secret 扫描报告的哈希或验证结果。

不要提供 API Key、系统凭据、完整数据库、`change-artifacts`、真实 `.env`、SSH Key、浏览器配置或未经授权的项目代码。
