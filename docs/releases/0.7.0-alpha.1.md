# OpenCode Desk 0.7.0-alpha.1

发布日期：2026-08-02

阶段：F - Python 解释器与真实调试

Git Tag：`v0.7.0-alpha.1`

## 阶段目标

在既有 Node.js/TypeScript 调试闭环上增加独立 Python Adapter，让用户无需污染项目虚拟环境即可完成
“发现解释器 → 保存运行配置 → 审批启动 → 命中断点 → 查看变量/调用栈 → 求值/单步 → 捕获异常 →
停止并清理”的真实调试流程，同时保持 DAP 核心和审批、脱敏、Diff 审核流程不依赖具体语言。

## 更新内容

### Python 解释器与建议配置

- 有界发现工作区 `.venv`、`venv`、`env`、当前激活环境与 PATH 解释器，不在打开项目时执行项目二进制。
- 工作区虚拟环境优先，并从有界 `pyvenv.cfg` 读取版本线索；找不到解释器时明确显示“尚未验证”。
- Python 运行配置表单提供候选解释器选择器，并保留手动 executable 路径覆盖能力。
- 根据入口和依赖元数据建议普通脚本、Django、Flask、FastAPI/uvicorn 与 pytest 配置。

### 真实 Python 调试

- 新增独立 `PythonDebugAdapterProvider`，通过共享 `DebugAdapterRegistry` 注册，不修改 Agent 或调试会话主流程。
- 随应用固定分发官方 `debugpy 1.8.21`，用户无需向项目依赖安装调试器。
- 支持真实普通/高级断点、线程、调用栈、局部变量、嵌套值、表达式求值、Step Over/Into/Out 和异常暂停。
- Adapter 通过回环随机端口连接 DAP；调试进程、debuggee 和子进程在停止、异常及应用退出时统一清理。

### 共享 DAP 基础设施

- Node 与 Python Adapter 共用帧解析、变量投影、路径映射和数据访问层。
- DAP 请求失败保留命令、响应和超时边界，启动错误显示解释器要求与可操作下一步。
- Python 输出、变量、异常与表达式复用现有 Secret 脱敏；工作区外源码路径不会暴露给 Renderer。

### Java 调试

- 固定分发 Eclipse JDT Language Server 1.60.0 与 Microsoft Java Debug Server 0.53.2，并记录官方来源、许可证、分发摘要与入口摘要。
- Java Provider 使用 JDK 21+ 运行 JDT LS，通过 stdio LSP 导入 Maven/Gradle 项目、编译工作区、解析主类与 classpath，再连接仅监听本机回环地址的 DAP 服务。
- Windows Maven 验收已命中真实源码断点，读取局部变量和调用栈，完成 Step Over，在 `IllegalStateException` 上暂停，并清理 debuggee、DAP 与 JDT LS；未修改系统 JDK、PATH、注册表或项目依赖。
- JDT LS 启动和打包校验按平台与 CPU 架构选择 `config_mac`/`config_mac_arm` 与 `config_linux`/`config_linux_arm`；公共 CI 的 macOS 构建固定为 `macos-15` ARM64 并显式生成 ARM64 DMG/ZIP，macOS ARM64/Linux x64 打包作业已以 JDK 21 完成真实 Java 调试验收。
- 函数/数据断点按 Adapter capability 发送真实 `setFunctionBreakpoints`/`setDataBreakpoints`；不支持时不发送请求并显示未验证原因。
- 异常策略支持指定类型暂停与忽略列表，规则按工作区持久化并在活动 Node/Python Adapter 中实时同步。
- 当前工作树在阶段 F 基础上新增外部 LLDB、Delve 和 NetCoreDbg Provider；三者不随应用分发，分别使用受管 stdio、回环 TCP、stdio DAP。Windows 已以 LLVM 22.1.8、Delve 1.26.3、NetCoreDbg 3.2.0-1092 对 C、C++、Rust、Go 和 .NET 真实项目完成断点、栈、局部变量、单步、退出及零残留验收；LLDB 实测修复了必须先发送 `launch` 再等待 `initialized` 的握手兼容性。

### 真实浏览器调试

- React、Vue 和 Next.js 的端口型配置路由到独立浏览器 Provider；常见 Vite、Next.js、CRA 和 Vue CLI 开发脚本会建议默认或显式端口。
- 浏览器 Provider 先以原结构化参数、`shell: false` 和最小环境启动经审批的开发服务器，确认回环端口就绪后，再由固定版本 js-debug 启动本机 Chrome 或 Edge。
- js-debug 的多目标 `startDebugging` 流程支持页面、Worker 与 iframe；停止、失败或应用退出会清理 Adapter、浏览器和开发服务器。
- Windows 上已使用真实 Chrome 验证源码断点、变量读取、Continue、单步以及浏览器/开发服务器退出清理。

### Node.js 远程与容器附加

- Node.js 兼容运行配置可保存经过严格 Schema 校验的 Inspector 主机、端口、目标环境和可选绝对 `remoteRoot`；该配置只允许“调试”，普通“运行”会拒绝。
- 随包 js-debug 使用标准 `attach` 请求连接已有目标。回环/本机转发端点为中风险，非回环端点为高风险；端点与风险原因进入不可变审批摘要。
- 应用不会自动运行 SSH、Docker 或容器命令，不会把本地环境值转发给目标，断开调试也不会终止远程或容器进程。
- Windows 真实集成测试使用独立 `node --inspect-brk` 目标验证了端口连接、源码断点、栈、局部变量和断开后目标仍存活。

### Python 远程与容器附加

- Python 运行配置可保存经过 Schema 校验的 debugpy 主机、端口、目标环境和可选绝对 `remoteRoot`，普通“运行”会拒绝附加配置。
- 应用直接连接目标进程由 `debugpy.listen()` 暴露的 DAP 端点，并发送标准 `attach` 与源码映射；不会错误启动第二个本地 Adapter。
- 停止附加会话只断开 DAP，不终止远程或容器进程，也不会转发本地环境变量或自动执行 SSH/Docker 命令。
- 真实 debugpy 目标集成测试已验证远端源码映射、断点、栈、局部变量、继续执行与清理。

### Electron 主进程与渲染进程调试

- 项目检测识别 `electron` 依赖，生成指向工作区 Electron 运行时的建议配置，并要求保存渲染进程调试端口。
- 同一固定 js-debug 服务以 `pwa-node` 启动主进程、以第二个 `pwa-chrome` 客户端附加渲染进程；多客户端线程、栈帧和变量引用使用隔离 ID。
- 审批摘要显示实际注入的 `--remote-debugging-address=127.0.0.1`、端口和完整参数；端口被占用时在启动前失败，避免附加到其他本机目标。
- Windows 真实验收已分别命中 `main.cjs` 与 `renderer.js` 源码断点、读取两侧局部变量，并验证断开后的 Electron 进程清理。

### 真实 Provider 发布门禁

- 新增 `pnpm test:providers:live`，可显式选择 10 个计划内 Provider，使用临时环境变量验证连接/模型列表和最小流式响应。
- Windows 验收可通过 `run-live-provider-acceptance.ps1` 交互输入配置；API Key 与自定义 Header 使用掩码提示，仅传给当前辅助进程及其测试子进程，并在成功或失败后恢复环境。
- 门禁默认不访问网络；未设置选择器时专用脚本失败，普通测试明确跳过，避免把“没有凭据、没有请求”误报为通过。
- 单 Provider 最长 60 秒、请求最多 32 token；测试不输出模型正文，API Key 和自定义 Header 值会在失败路径再次脱敏。

### ProjectTask、多服务与端口

- ProjectTask 支持创建、编辑、删除、依赖、审批运行、停止、重试、输出、历史，以及运行/调试前后钩子。
- 组合运行配置通过一次批量审批并发启动多个服务，保留独立输出、状态和停止控制，并支持单服务失败时停止全部。
- 运行配置可声明端口；启动前检测占用与重复服务，界面显示 PID/进程名，终止外部占用者必须明确确认并复核 PID。
- 文件树、聊天栏和底部面板尺寸均可拖动或键盘调整，并通过本地设置跨重启恢复。
- 核心工作台、设置、运行、调试、任务、Git、终端、审计和审批界面均可在简体中文与英文之间切换。

### 打包可靠性

- 主进程保留唯一 `BrowserWindow` 的强引用，并在真实关闭后释放，避免长时间运行时 JavaScript 包装对象被回收导致应用以退出码 0 意外结束。
- 增加主动触发主进程垃圾回收的窗口生命周期回归，并在稳定性验收期间按分钟施加 GC 压力。
- Renderer 构建前清理历史 hashed bundle，避免旧产物累积进入 ASAR。
- 打包前校验 `apps/desktop/node_modules` 中全部 15 个生产依赖，链接缺失时立即失败。
- electron-builder 将 `debugpy` 作为只读资源、`node-pty` 原生文件作为 ASAR unpack 内容分发。
- macOS 打包后、签名前恢复 `node-pty` `spawn-helper` 的执行位，运行时完整性校验会拒绝不可执行的 helper。
- 修复本地损坏 pnpm 链接层导致 `electron-updater` 未进入 ASAR、启动只显示主进程错误对话框的问题。
- 打包后校验目标平台可执行格式、ASAR、两个调试适配器和 `node-pty` 原生模块，交叉构建缺少目标 ABI 时直接失败。
- 生成确定性的 CycloneDX 1.6 SBOM、完整 workspace 依赖审计、随包第三方许可证审计和 Secret 扫描报告，并将四者纳入发布校验和。
- CI 与签名发布工作流使用 Node 24 运行时的 `actions/upload-artifact@v7` 和 `actions/download-artifact@v8`；下载阶段默认在服务端摘要不一致时失败，避免继续使用已弃用的 Node 20 Action 运行时。
- 活动编辑器除文件系统事件外还会执行有界磁盘对账，避免平台文件监听漏报时长期显示旧内容；异步读取完成后会重新确认当前工作区、标签和保存状态，防止陈旧读取覆盖用户输入。
- 调试继续、暂停和单步控制在前一请求完成前禁用并拒绝重入，避免相邻 DAP 控制请求交错；跨平台 E2E 临时目录清理使用有限次数重试处理 Chromium 退出后的短暂文件占用。

## 安全与权限

- 解释器发现只读取文件系统元数据；建议配置仍需用户保存，运行/调试仍需对不可变命令摘要逐次批准。
- “记住允许”只会放行完全相同的可执行文件、工作目录和参数数组；旧版本保存的宽泛允许规则按失败关闭处理，不会自动执行新的参数载荷。
- Provider JSON 与 SSE 正文使用增量原始字节上限、停滞超时和总体时长限制，分块传输、SSE 注释、协议框架与持续小块输送都不能绕过资源边界。
- Agent 默认工具安全额度由 20 次提高为 64 次、模型轮次由 8 轮提高为 24 轮；触顶时完整记录未执行工具结果、保存会话进度，并提供可重试的继续提示，避免留下不完整工具调用历史。
- 文件、Git、终端、命令与运行服务解析工作区时只接受当前显式打开的工作区，持久化的最近工作区 ID 本身不再构成磁盘访问授权。
- Python、debugpy 与用户程序均以参数数组和 `shell: false` 启动，不自动请求管理员权限。
- 调试器仅监听 `127.0.0.1` 随机端口，不开放局域网入口。
- 环境变量、输出、异常、变量树与 AI 调试上下文继续执行敏感值脱敏和长度限制。
- AI 修复仍必须进入 FileChange Diff 审核；不会自动应用修改或自动重新调试。
