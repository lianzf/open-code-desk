# OpenCode Desk 0.2.0-alpha.1

发布日期：2026-08-01  
阶段：A - 项目识别与运行配置基础  
Git Tag：`v0.2.0-alpha.1`

## 阶段目标

建立 IDE 运行与调试功能的第一层稳定边界：在不执行项目代码的前提下识别项目类型、生成运行配置建议、安全保存用户配置，并通过类型安全 IPC 暴露给桌面端。

## 更新内容

### 项目类型识别

- 识别 Node.js、TypeScript、React、Vue、Next.js。
- 识别 Java Maven、Java Gradle 和 Spring Boot。
- 识别 Python、C、C++、.NET、Go、Rust、普通脚本和自定义项目。
- 使用固定项目标志文件、根目录有限枚举和有界文本读取，不递归扫描整个工作区。
- 拒绝读取符号链接标志文件，`package.json` 最大读取 256 KiB，其他构建描述前缀最大读取 64 KiB。
- 从包管理器锁文件、scripts 和常见入口生成结构化 `executable + args` 建议，不执行任何脚本。

### 运行配置

- 新增纯 TypeScript `ProjectType`、`RunConfigurationDraft`、`RunConfiguration` 与项目识别证据模型。
- 新增严格 Zod 请求与响应 Schema，覆盖检测、列表、保存、删除和默认配置。
- 新增独立 `run.ipc.ts`；主进程验证工作区归属，preload 对请求和响应进行双向校验。
- 新增 SQLite migration 8：`run_configurations` 与 `workspace_run_settings`。
- 保存多个项目绑定配置并设置默认配置，应用重启后仍可恢复。

### 凭据安全

- 普通环境变量可随运行配置保存。
- 敏感环境变量明文只在主进程短暂进入 `SecureSecretStore`。
- SQLite 运行配置只保存 `secretRef`；公开 DTO 只返回 `configured` 状态，不返回凭据引用或明文。
- 更新和删除配置时轮换或清理旧凭据引用。

### 跨平台质量

- executable 归一化先统一路径分隔符，使 Linux CI 能识别 Windows 路径。
- Vitest 统一使用 15 秒集成测试预算，覆盖原生 PTY、Git 和多文件事务在并发负载下的合理耗时。
- README 补齐功能、技术栈、开发环境、运行、构建、模型配置、安全和常见问题。

## 数据库升级

应用启动时自动从 `PRAGMA user_version = 7` 迁移到版本 8。迁移新增运行配置表，不修改既有工作区、Provider、会话、工具、文件变更或命令记录。用户无需手动操作数据库。

## 安全边界

本版本不会自动执行检测到的 `package.json` script、构建工具或项目入口。运行配置只是数据和建议；阶段 B 将在明确显示 executable、args、工作目录和风险原因并获得用户批准后，才允许启动项目进程。

## 已知限制与下一阶段

- 尚无运行配置 UI、启动/停止/重启、PID、实时输出或运行历史。
- 尚无 DAP client、Node.js Debug Adapter、断点、线程、调用栈、变量或单步控制。
- 下一阶段将实现独立的受管运行进程服务和运行工具栏，不复用 Agent 命令记录伪装 IDE Run。
