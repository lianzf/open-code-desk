# OpenCode Desk 0.6.0-alpha.1

发布日期：2026-08-02

阶段：E - 高级断点与异常策略

Git Tag：`v0.6.0-alpha.1`

## 阶段目标

减少程序员为了复现“第 N 次循环、特定请求或特定数据状态”而反复修改业务代码、插入临时日志、重启
项目和清理日志的成本。在阶段 D 真实 Node.js/TypeScript 调试闭环上，增加条件断点、命中次数、
日志断点和按工作区持久化的异常暂停策略；所有能力必须连接真实 DAP，不能只显示静态图标。

## 更新内容

### 高级断点

- Monaco 行号槽保留单击快速增删普通断点，右键菜单可打开高级断点编辑器。
- 可设置条件表达式、命中次数和日志消息；断点列表显示类型、定义摘要、启用状态和验证状态。
- 条件与命中次数可组合使用；日志断点支持 js-debug 插值并保持程序继续运行。
- Node Adapter 将 `condition`、`hitCondition`、`logMessage` 原样映射到 DAP `setBreakpoints`。
- 活动调试会话中编辑、启用、禁用或删除断点会立即重新同步对应源文件。

### 异常暂停策略

- 断点面板新增“不因异常暂停 / 仅未捕获异常 / 全部异常”三档策略。
- 启动调试时在 configurationDone 前设置策略；运行中修改会立即调用 DAP
  `setExceptionBreakpoints`，无需重启项目。
- 设置按 workspace ID 保存，应用重启后与断点定义一起恢复。

### 架构与持久化

- 新增 `DebugConfigurationCoordinator`，把断点、监视和调试设置从会话生命周期中拆分。
- 新增 `DebugSettingsRepository` 和 `debug_settings` 表；migration 11 为断点增加 condition、
  hit_condition、log_message 列。
- migration 11 支持从 user_version 10 原地升级，已有普通断点内容和身份保持不变。
- 调试会话服务 375 行、Renderer 调试 Store 377 行，符合单个业务文件原则上不超过 400 行的约束。

### IDE 使用痛点改进

- 定位循环/重试/批处理中的特定一次执行时，无需改代码增加计数判断。
- 观察线上相似流程或高频调用的状态时，可使用日志断点，避免暂停造成时序变化。
- 条件、命中规则、验证结果和 Adapter 错误在同一断点列表可见，减少无效断点排查时间。
- 异常策略绑定项目而非全局偏好，切换工作区时不会把一个项目的高噪声策略带到另一个项目。

## 安全与权限

- 高级断点定义由用户显式编辑，只在已经批准启动的调试会话内发送给 Adapter。
- 条件或日志消息不会进入 Shell、不会作为系统命令执行，也不会赋予 Agent 新工具权限。
- IPC 输入使用 Zod 严格校验和长度上限；断点路径继续受工作区边界约束。
- 日志断点输出复用调试输出的 Secret 脱敏、长度限制和持久化策略。
- 异常策略仅接受固定枚举，实时切换不等于重新启动、执行命令或修改文件的授权。

## 已知限制与下一阶段

- 完整调试和 AI 修复闭环当前只覆盖 Node.js/TypeScript；其他语言 Adapter 尚未接入。
- 函数断点、数据断点、特定异常类型和异常忽略列表尚未实现。
- 日志断点语法与条件表达式语义由具体 Adapter 决定，后续多语言接入需提供能力检测与表单提示。
- 调试/运行底部面板仍不支持拖动调整高度，跨多进程/多服务因果关联尚未实现。
- 未签名安装包仅用于开发验证；正式发布仍需 Windows 签名、macOS 签名/notarization 和干净设备验收。
