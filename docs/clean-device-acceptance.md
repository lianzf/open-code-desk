# 干净设备独立验收

本清单用于正式发布前的人工放行。自动化 E2E、CI runner 或开发者本人复验不能替代本记录；验收人员应独立按步骤操作，并为每一项留下不含密钥的证据。任一核心步骤失败、被跳过或证据不足，都必须判定为不通过。

## 验收角色与环境

- 验收人员未参与本候选版本的实现或自动化测试编写。
- Windows 与 macOS 使用干净设备、全新虚拟机或全新系统用户；设备上不依赖 Node.js、pnpm 或仓库源码启动应用。
- Linux 使用受支持桌面环境，并启用 Secret Service 或 KWallet；不得接受 `basic_text` 密钥后端。
- 使用专门的无敏感数据测试仓库。运行任何项目脚本前先检查内容并接受应用内安全提示。
- Provider 凭据只在验收期间通过应用 UI 或本机临时环境变量输入。报告不得记录 API Key、Header 值、Token、Cookie、连接密码或完整敏感变量。
- 每个平台至少由一名验收人员独立完成；Windows 与 macOS 正式产物必须先通过平台签名检查。

## 平台安装与生命周期

### Windows

- [ ] `Get-AuthenticodeSignature` 返回 `Valid`，签名主体与发布者一致。
- [ ] 使用 NSIS 安装包完成交互式安装，不需要开发环境或管理员模式运行应用。
- [ ] 开始菜单和桌面入口可启动应用，首屏无白屏或安全警告。
- [ ] 最小化、最大化、恢复和关闭均正常。
- [ ] 正常关闭后没有 OpenCode Desk、调试器或被应用启动的项目残留进程。
- [ ] 使用同版本覆盖安装或上一正式版升级后，非敏感设置和历史会话仍可恢复。
- [ ] 卸载成功；保留或清除用户数据的实际结果与界面说明一致。

### macOS

- [ ] `codesign --verify --deep --strict` 成功。
- [ ] `spctl --assess --type exec` 成功，Gatekeeper 不要求绕过安全策略。
- [ ] `xcrun stapler validate` 确认 notarization ticket 有效。
- [ ] 从 DMG 安装到 Applications 后可启动，首屏无白屏。
- [ ] 窗口生命周期、正常退出、重新启动和升级恢复正常。
- [ ] 退出后没有 OpenCode Desk、调试器或被应用启动的项目残留进程。

### Linux

- [ ] AppImage 的 SHA-256 与发布清单一致，赋予执行位后可直接启动。
- [ ] 首屏无白屏，文件选择器、终端和窗口生命周期正常。
- [ ] Secret Service 或 KWallet 可用；应用没有退化到明文密钥保存。
- [ ] 退出后没有 OpenCode Desk、调试器或被应用启动的项目残留进程。

不适用的平台部分必须在报告中说明原因；正式 Windows/macOS 发布不得把对应平台签名、安装或启动步骤标为不适用。

## IDE 调试与 AI 修复闭环

- [ ] 应用识别真实项目类型，并生成可编辑的运行配置。
- [ ] 新建、复制、修改、设为默认和删除运行配置后，重启仍能恢复。
- [ ] 一键运行项目，实时显示 PID、工作目录、输出、端口、时长和退出码。
- [ ] 停止、重新运行以及端口冲突处理符合授权边界。
- [ ] 在 Monaco 行号区域设置真实断点，调试器将其标记为已验证。
- [ ] 启动调试后命中断点，当前执行行高亮并可返回暂停位置。
- [ ] 查看并切换线程、调用栈、栈帧、局部变量和可展开对象。
- [ ] 新增监视表达式并验证求值结果或明确错误。
- [ ] 分别执行继续、暂停、Step Over、Step Into、Step Out 和运行到光标。
- [ ] 触发真实运行时异常，应用定位文件和行并显示类型、消息与调用栈。
- [ ] 选择“交给 AI 分析”，预览中不存在 API Key、Token、密码或完整敏感环境变量。
- [ ] AI 基于调试上下文读取相关代码并生成修复 Diff。
- [ ] 未批准前文件不变；批准后应用修改并显式重新运行或重新调试。
- [ ] 修复后异常不再出现，或报告明确记录仍失败的原因。
- [ ] 停止调试并退出应用后，debuggee、DAP、语言服务器和项目子进程均已清理。

至少使用一个真实 Node.js/TypeScript 项目完成上述全流程。Java、Python、浏览器、Electron、C/C++、.NET、Go 和 Rust 按发布范围分别记录可用工具链、实际覆盖步骤和结果，不得用“界面存在”替代真实断点证据。

## 安全、持久化与故障检查

- [ ] 检查应用数据库、普通配置、localStorage、日志、崩溃报告、审计导出和 Git 工作树，未发现明文 API Key 或敏感 Header。
- [ ] 认证失败、模型不存在、限流、超时和上下文过长均显示发生原因、是否可重试及下一步。
- [ ] 取消文件、命令或外部目录授权后，操作没有继续执行。
- [ ] 路径穿越、工作区外路径、敏感文件和未授权符号链接被拒绝。
- [ ] 高风险命令被拒绝或要求独立确认；应用未以管理员/root 身份默认运行。
- [ ] 网络中断、Provider 不可用、文件冲突、测试失败和数据库异常不会导致应用退出或历史全部丢失。
- [ ] 连续创建 20 个会话、切换模型并执行失败命令后，应用仍可操作。
- [ ] 自动更新只接受签名发布来源；失败时保留当前可运行版本。
