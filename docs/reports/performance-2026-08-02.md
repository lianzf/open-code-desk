# 10,000 文件性能验收报告

日期：2026-08-02（最终源码复验：2026-08-03）

## 结论

OpenCode Desk 在真实创建的 10,000 文件临时工作区中通过增量文件树、名称搜索内存边界和搜索取消验收。测试不会把工作区文件内容预加载到内存；根文件树只返回首层的 100 个目录，内容搜索仍受文件数与结果数上限保护。

## 环境

| 项目     | 值                                 |
| -------- | ---------------------------------- |
| 操作系统 | Windows 11 家庭中文版 10.0.26200   |
| 处理器   | AMD Ryzen 7 H 260，16 个逻辑处理器 |
| 内存     | 31.3 GiB                           |
| Node.js  | 25.2.1                             |
| pnpm     | 10.29.2                            |

## 场景与结果

测试工作区包含 100 个一级目录，每个目录包含 100 个 TypeScript 文件，共 10,000 个文件。

| 指标               |        实测 |                   门槛 | 结果 |
| ------------------ | ----------: | ---------------------: | ---- |
| 测试夹具创建       | 8,729.45 ms | 仅记录，不作为产品门槛 | 记录 |
| 根目录增量加载     |    31.44 ms |             < 5,000 ms | 通过 |
| 根目录返回条目     |  100 个目录 |     不递归返回文件内容 | 通过 |
| 名称搜索遍历       |   680.08 ms |            < 15,000 ms | 通过 |
| 目标名称命中       |     100/100 |       必须完整覆盖夹具 | 通过 |
| 已取消内容搜索返回 |     1.41 ms |             < 1,000 ms | 通过 |
| 文件树堆内存增量   |     0 bytes |               < 64 MiB | 通过 |
| 文件树 RSS 增量    |     0 bytes |              < 128 MiB | 通过 |

名称搜索和内容搜索均使用 `AbortSignal` 验证了预取消行为。测试还验证了 10,000 文件加目录项不会因遍历上限丢失尾部结果。

## 复现

```powershell
pnpm test:performance
```

测试实现位于 `apps/desktop/src/main/filesystem/workspace-performance.acceptance.ts`，使用独立的 `vitest.performance.config.ts`，不会增加日常单元测试的文件系统负担。

## 范围

本报告证明当前 Windows 验收机上的 10,000 文件增量加载、名称搜索、有界内存和取消语义。它不替代 4 小时稳定性测试、macOS/Linux 原生性能测试或更大规模工作区基准。
