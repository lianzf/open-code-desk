# 使用指南

## 1. 打开和管理项目

启动后点击“打开项目”，通过系统目录选择器授权一个本地目录。应用只把该目录作为当前工作区；工作区外目录必须再次通过系统选择器显式授权。

文件树支持展开、收起、刷新、创建、重命名、移动和删除。文件名搜索与代码内容搜索共用左侧搜索入口；内容搜索可取消。打开文本文件后使用 Monaco Editor 编辑，`Ctrl+S`（macOS 为 `Cmd+S`）保存。文件在外部发生变化时，应用会阻止用陈旧基线静默覆盖。

## 2. 配置并切换模型

进入“模型设置”，新增预置 Provider 或 OpenAI Compatible 服务，填写 Base URL、API Key 和 Model ID，再执行连接测试。密钥保存后不会回填到输入框。详细字段和错误处理见[模型配置指南](model-configuration.md)。

工作台模型选择器可随时切换当前模型；默认、快速和高级推理模型分别用于一般对话、低延迟操作和需要更强推理的任务。

## 3. 完成一次 AI 编程任务

1. 新建会话并描述需求。
2. 在上下文托盘添加当前文件、多个文件、文件夹、选中代码、粘贴文本、图片、终端输出、Git Diff 或报错信息。
3. Agent 显示分析、计划、工具执行、等待授权、修改、测试和完成等状态。
4. 只读工具按当前权限规则读取或搜索项目；不会自动上传整个项目。
5. AI 提出文件修改时，先进入 Diff 审核区。可逐文件或批量批准、拒绝，也可编辑提案后再应用。
6. 文件只有在批准后才写入；写入冲突或事务中途失败会停止并回滚。
7. AI 提出命令时，审批区显示实际 executable、参数、目录和风险原因。批准后才会启动，并实时显示 stdout、stderr、退出码和状态。
8. 根据测试结果继续对话，直到计划步骤真实完成。

最近一次已应用文件事务可以回滚；若文件之后又被外部修改，系统会阻止不安全回滚。

## 4. 会话与历史

会话支持新建、重命名、删除、搜索、停止生成、重新生成、复制消息和导出 Markdown。消息、模型、工具调用、文件修改、命令结果、错误与任务状态写入本地数据库。应用重启后，重新打开最近项目即可恢复会话和任务记录。

## 5. 运行项目

打开项目后，顶部运行工具栏会显示检测到的项目类型和建议运行配置。建议配置不会自动执行项目脚本；用户必须检查并保存。

运行配置可以设置 executable、参数、运行时参数、工作目录、环境变量引用、环境文件、启动前/后任务、端口和输出终端。保存后选择“运行”，审核不可变命令摘要并批准。运行面板显示 PID、启动时间、工作目录、输出、退出码和运行时长，并支持停止、重新运行和终止全部由应用启动的进程。

ProjectTask 用于构建、清理、测试、启动、打包、部署、Lint、类型检查和自定义任务；可配置依赖及运行/调试前后钩子。组合运行配置可并发启动前后端或多个服务，并支持分别停止或一键停止。

## 6. 调试 Node.js/TypeScript、Python、浏览器、Electron、C/C++、Rust、Go 和 .NET

1. 选择或创建可调试的运行配置。
   - Node.js/TypeScript 与 Python 调试器随应用分发；Python 可选择工作区虚拟环境或手动解释器。
   - React、Vue 或 Next.js 前端配置需要填写开发服务器端口。常见 Vite、Next.js、CRA 和 Vue CLI 脚本会建议默认或显式端口；调试时应用先启动经审批的开发服务器，再使用本机 Chrome 或 Edge 打开回环 URL。
   - 检测到 `electron` 依赖时会建议 Electron 配置。确认本地 Electron 可执行文件、应用参数和渲染进程调试端口；批准后，应用以 `pwa-node` 调试主进程，并通过仅监听 `127.0.0.1` 的 Chromium DevTools 端口以 `pwa-chrome` 附加渲染进程。审批摘要会显示注入的回环地址、端口和完整启动参数。
   - Node.js 兼容配置可启用“附加到已有 Node.js 调试目标”，选择远程主机或已转发端口的容器，填写 Inspector 主机、端口和可选目标源码根目录。该配置只能使用“调试”，不能普通“运行”。应用不会自动执行 SSH、Docker 或容器命令。
   - C/C++/Rust 需要系统 PATH 中存在 `lldb-dap`，运行配置必须指向已编译二进制。若需先构建，请配置 pre-debug ProjectTask，不要把 `cargo`、`cmake`、`make`、`ninja` 或 `msbuild` 作为调试目标。
   - Go 需要 PATH 中存在 `dlv`；简单的 `go run <package>` 配置会交给 Delve 构建，也可直接选择已编译 Go 二进制。
   - .NET 需要 PATH 中存在 `netcoredbg`，运行配置必须指向已构建的 `.dll` 或 `.exe`；把 `dotnet build` 配置为 pre-debug ProjectTask。
2. 在编辑器行号区域设置断点；高级菜单可配置条件、命中次数、日志、函数、数据和异常断点。
3. 点击“调试”，检查启动摘要并批准。
4. 命中断点后，当前执行行会高亮；调试面板显示线程、调用栈、局部变量、监视表达式和断点验证状态。
5. 使用继续、暂停、Step Over、Step Into、Step Out、运行到光标、重启或停止。
6. 独立调试控制台显示程序输出、前端开发服务器输出、Electron 主/渲染进程输出、调试器输出、异常和表达式求值结果。

函数/数据断点是否可用取决于当前 Adapter capability；不支持时会明确显示未验证，不会伪报成功。

远程主机推荐先建立本机转发，例如 `ssh -N -L 9229:127.0.0.1:9229 user@host`，再把配置主机设为 `127.0.0.1`、端口设为 `9229`。容器应把 Inspector 端口只映射到本机回环地址。直接填写非回环主机会标记为高风险并要求逐次批准；停止或断开调试只关闭本机 Adapter，不终止目标进程。

## 7. AI 辅助调试

程序暂停或抛出异常后，点击“交给 AI 分析”。先在预览中选择要附加的源码、调用栈、变量、异常、输出、Git Diff、运行配置和依赖信息。应用在发送前脱敏常见密码、Token、API Key 和连接凭据。

AI 可以继续读取相关项目文件并提出修复 Diff，但不能自动修改变量、跳过代码、重启服务或直接写文件。用户批准 Diff 后，必须再次显式启动调试来验证结果。

## 8. Git、终端和权限

Git 面板显示当前分支、已修改、未跟踪、暂存状态和 Diff。集成终端供用户交互使用；Agent 命令仍走独立审批流程。

权限设置可控制工作区普通读取是否自动允许、阻止的相对路径和显式外部目录。文件写入、删除、命令执行和外部访问默认需要确认；提权、广泛删除、系统配置、读取凭据和下载后执行等高风险模式会拒绝或要求独立确认。

## 9. 故障处理

- 连接失败：检查 Base URL、网络、API Key 权限、Model ID 和服务能力；界面会区分认证、模型不存在、限流、超时、上下文过长和服务不可用。
- 文件保存失败：检查外部修改、权限、符号链接逃逸或敏感路径策略，刷新后重新生成 Diff。
- 命令或运行失败：查看实际参数、工作目录、stderr、退出码、端口冲突和任务钩子结果。
- 调试失败：检查 Adapter 可用性、解释器/入口或已编译二进制、断点验证状态和调试控制台错误；外部语言还需确认 `lldb-dap`、`dlv` 或 `netcoredbg` 已加入 PATH。
- 数据库或应用内部异常：在设置中查看本地崩溃记录；报告会脱敏且不会自动上传。

更完整的启动、Provider、文件、命令、运行、调试和更新排障步骤见[故障排查指南](troubleshooting.md)；本地保存内容、联网边界和彻底清除说明见[隐私与本地数据说明](privacy.md)。
